# Деплой Next.js + Prisma + PostgreSQL

Эта памятка описывает базовый процесс для сайта с формой заявок и админкой.

## Как это работает

1. Посетитель отправляет форму на сайте.
2. API-роут `/api/leads` проверяет данные и создает запись в таблице `Lead`.
3. Prisma подключается к PostgreSQL через `DATABASE_URL`.
4. Админка `/admin/leads` читает заявки из этой же базы.
5. Пароль админки хранится в `ADMIN_PASSWORD`, а не в коде.

## Что нужно подготовить

- GitHub-репозиторий с кодом сайта.
- PostgreSQL-база: Neon, Supabase, Prisma Postgres, Railway, Render или свой VPS.
- Хостинг для Next.js: Vercel, Netlify, Render, VPS с Node.js.
- Три переменные окружения:
  - `DATABASE_URL`
  - `DIRECT_URL` при необходимости
  - `ADMIN_PASSWORD`
  - `NEXT_PUBLIC_SITE_URL`

## Порядок деплоя

1. Создать PostgreSQL-базу у провайдера.
2. Скопировать connection string в формате `postgresql://...`.
3. Добавить `DATABASE_URL` в `.env` локально и в переменные окружения хостинга.
4. Добавить `DIRECT_URL`, если провайдер дает отдельную прямую строку для миграций.
5. Добавить сильный пароль в `ADMIN_PASSWORD`.
6. Указать публичный адрес сайта в `NEXT_PUBLIC_SITE_URL`.
7. Установить зависимости: `npm install`.
8. Сгенерировать Prisma Client: `npm run prisma:generate`.
9. Применить миграции к базе: `npm run prisma:deploy`.
10. Собрать сайт: `npm run build`.
11. Запустить или задеплоить сайт.
12. Проверить форму заявки и страницу `/admin/leads`.

## Что важно запомнить

- `DATABASE_URL` никогда не коммитят в Git.
- `DIRECT_URL` тоже не коммитят в Git.
- `prisma/schema.prisma` описывает модели данных.
- `prisma/migrations` хранит SQL-историю базы.
- `npm run prisma:migrate` используют при разработке новой миграции.
- `npm run prisma:deploy` используют на сервере, чтобы применить уже готовые миграции.
- Если сайт уже работал с другой базой, сначала делают резервную копию данных.

## Перенос данных

Для нового сайта обычно переносить нечего: достаточно создать PostgreSQL-базу и применить миграции.

Если в старой SQLite-базе уже есть реальные заявки, безопасный минимум:

1. Скачать заявки через CSV-экспорт в админке.
2. Подключить PostgreSQL.
3. Применить миграции.
4. Импортировать нужные заявки в новую базу отдельным скриптом или вручную через админ-инструмент.

На клиентских проектах с реальными данными сначала делают backup, затем тестовый импорт, и только после проверки переключают сайт на новую базу.
